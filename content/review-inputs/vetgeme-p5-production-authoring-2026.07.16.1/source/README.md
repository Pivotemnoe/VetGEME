# VetGEME P5 production authoring package

Версия пакета: `2026.07.16.1`.

Это отдельный пакет данных для уже существующего P5-планировщика ресурсов. Он не переписывает движок, не меняет визуальный дизайн и не содержит медицинских диагнозов или результатов исследований.

## Что подготовлено

- 10 сотрудников с ролями, навыками, доступностью и условиями найма;
- 12 функциональных помещений с вместимостью и условиями открытия;
- 27 физических ресурсов оборудования из утверждённого реестра возможностей;
- 14 операционных этапов визита;
- операционная классификация всех 447 возможностей клиники;
- P5-задачи для всех 361 исследований P3;
- приоритет, срочность, safe-route и handoff для всех 1 864 применений исследований;
- рекомендательный 30-дневный график двух стартовых врачей без отмены выбора игрока;
- правила усталости, делегирования, отсутствий, обслуживания, перегрузки и передачи активной задачи.

## Главная граница

P5 отвечает только на вопросы «кто, где, чем и сколько времени выполняет работу». Клиническая истина и результаты остаются в медицинском пакете/P3, собственность, расходники и обслуживание — в P6, события и отсутствия — в P7. Визуальный слой только отображает состояние.

`runtimeEligible` намеренно остаётся `false`: программист должен подключить адаптер, выполнить browser smoke и save/reload replay. Текущий игровой пул не нужно выключать до прохождения этих gate-проверок.

## Основные файлы

- `source/p5-policy.json` — авторский источник правил P5;
- `generated/resource-catalog.json` — сотрудники, помещения и оборудование;
- `generated/visit-task-catalog.json` — этапы визита;
- `generated/capability-operations-map.json` — покрытие 447 возможностей;
- `generated/research-task-catalog.json` — задачи для 361 исследований;
- `generated/investigation-usage-task-map.json` — 1 864 контекстных применения;
- `generated/recommended-30-day-staffing.json` — рекомендательный график;
- `generated/operational-policies.json` — усталость, смены, handoff и safe route;
- `PROGRAMMER_HANDOFF.md` — полноценное задание на интеграцию;
- `reports/VALIDATION_REPORT.json` — машинный отчёт проверки.

## Повторная сборка и проверка

```bash
node p5-production-authoring/scripts/build-p5-package.mjs
node p5-production-authoring/scripts/validate-p5-package.mjs
```

Оба скрипта запускаются из корня репозитория.
