# Operational package contract v2

## Общие поля

Каждый каталог имеет `schemaVersion`, стабильные `catalogId`/`catalogVersion`,
явный `status` и `runtimeEligible`. ID не выводятся из отображаемого текста.

## P3

`research-catalog.json` даёт один record на каждый `researchId` медицинского
пакета. `investigation-usage-policy.json` даёт один record на каждую позицию
`investigations[]`, а не только на уникальный тест.

Медицинский результат может прийти только из соответствующей презентации.
Operational layer отвечает за заказ, срок, исполнителя, стоимость, review,
контакт, handoff и направление, но не генерирует результат.

Порядок due-time:

1. точный numeric range capability превращается в детерминированный срок через
   `orderId + providerId + catalogVersion`;
2. categorical turnaround выбирается по таблице и уже определённому urgency band;
3. external cutoff и календарь провайдера применяются после выбора длительности;
4. повторная загрузка использует сохранённый due time, а не вычисляет новый.

## P4

Внешность, persistent profile и mutable state — разные сущности. Appearance seed
не может выбирать поведение. Поведение не может раскрывать диагноз. Темперамент
влияет только на время, handling, требования к ресурсам, состояние и качество
образца.

Crosswalk развёрнут по всем фактическим тегам. Runtime не должен повторять
token-matching сборщика: он импортирует готовые явные записи.

`matchTokens` в policy — только воспроизводимый авторский инструмент. Источник
runtime-решений — `p4-explicit-behavior-crosswalk.json`.

## P6

Ledger — единственный источник денег. Визуальный предмет не означает владение.
Физический ресурс активен только при владении, доставке, завершённом обучении и
исправном обслуживании. Конкретная задача дополнительно требует нужные
расходники и свободную ёмкость.

Четыре оси репутации остаются раздельными: `clinical`, `communication`,
`accessibility`, `organization`. Среднее допустимо только для отчёта и не даёт
скрытых игровых прав.

Баланс применяется к новой кампании. Legacy money/reputation не угадываются и
save schema не меняется.

## P7

Расписание дня создаётся и сохраняется до выбора целей. Цель не требует
конкретного персонажа, пациента, диагноза или семейства. События не меняют
медицинскую генерацию.

`catalogRef` и envelope должны быть точными. Once-event после reload не
повторяется. Endless day возможен только после записанного ending.

## Fail-closed activation

Импорт допустим только при совпадении версий, успешной проверке ссылок и наличии
явного runtime adapter. Любое неизвестное поле/ID блокирует конкретную запись и
оставляет безопасный referral/старый 30-card pool; оно не заменяется догадкой.
