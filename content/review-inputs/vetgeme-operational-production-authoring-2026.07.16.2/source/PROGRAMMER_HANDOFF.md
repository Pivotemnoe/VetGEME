# Задание программисту: P3/P4/P6/P7 `.2`

## Цель

Подключить авторские каталоги пакета без изменения медицинских текстов,
визуального дизайна и действующей схемы сохранения. Медицинский пакет `.40` и
P8 `.2` остаются отдельным источником клинической истины.

## Обязательный порядок

1. Сделать P0-аудит `HEAD`, ветки, status, уже подключённых `.1`, `.40`, P8 `.2`
   и действующих namespaces. Не дублировать каталоги и не переписывать
   пользовательские `art/` и `handoff/`.
2. Импортировать пакет как review input с provenance, digest и `runtimeEligible:
   false`.
3. P3: читать только `p3-explicit-research-routes.json`. Не восстанавливать
   провайдера по названию ID. Доступность проверять по state predicates; ни один
   флаг `owned/delivered/trained/maintained/stock` не ставить автоматически.
4. P4: читать только explicit crosswalk. Не применять `includes`, regex или
   первый совпавший токен. Structured safe alternative обязан сохранять
   `factId`, route и владельца медицинского результата.
5. P5/P6: использовать exact resource crosswalk. Покупка создаёт pending asset;
   доставка, готовность, обучение, обслуживание и наличие расходников — разные
   состояния и команды.
6. P7: подключить 93 evidence-resolver записи, digest envelopes и idempotent
   event records. Цели дня выбираются после сохранённого расписания и не требуют
   конкретного пациента, семьи или диагноза.
7. Не активировать production pool одним фактом успешного импорта. Activation
   manifest создаётся отдельно только после всех gates.

## Требования к save/reload

- созданный день сохраняется сразу и не генерируется повторно;
- event repeatability и cooldown переживают reload;
- состояния активов, доставки, обучения, обслуживания, склада и обязательств
  результатов восстанавливаются без визуальных догадок;
- режимы `current`, `legacy-v1`, `tier-01-v2` не смешивают сохранения;
- при необходимости новой схемы сначала предложить version + migration plan,
  не менять её молча.

## Fail-closed правила

- неизвестный capability/resource/evidence ID блокирует действие и пишет
  понятную диагностику;
- отсутствие оборудования всегда оставляет безопасное направление;
- P3/P4/P5/P6/P7 не создают и не правят медицинский результат;
- renderer и DOM не владеют симуляцией;
- юмор и реплики не скрывают единственный путь к важному факту.

## Приёмочные проверки

- bundled validators пакетов `.2`;
- JS syntax и `git diff --check`;
- минимум 10 000 seeded campaign runs и P5 demand runs;
- browser smoke: локальное исследование, недоступное исследование с referral,
  ожидание внешнего результата, review/contact, покупка → доставка → обучение →
  работа → обслуживание → stockout;
- save/reload каждого перехода;
- reset/cancel во всех трёх режимах;
- Docker build/runtime отдельно от текущего контейнера;
- независимый review P0/P1.

## Отчёт

Отдельный коммит. В отчёте указать HEAD, входные digest, адаптеры, миграции,
browser/Docker evidence, что намеренно не менялось и оставшиеся gates. Не
объявлять полный master package завершённым, пока medical pool остаётся 0 или
P9 не подключён.
