# Pet Clinic / Темичеввет - Screen Structure

## 1. Главный Принцип Интерфейса

Игра не должна быть одним экраном с кучей кнопок.

Нужна структура:

- карта клиники показывает помещения и поток пациентов;
- прием пациента открывается отдельно;
- развитие клиники вынесено в отдельные вкладки;
- медицинские решения показываются в карточке случая;
- экономические решения показываются в управленческих экранах.

## 2. Основной Экран Клиники

Главный экран - рабочая карта дня.

Для первого этапа комнаты и мебель фиксированы. Режима строительства и свободной расстановки нет. Анимируются только персонал, владельцы и животные. Администратор не является обязательным стартовым сотрудником: без него пациенты самостоятельно занимают очередь, а врач тратит часть времени на организационные действия.

Макет:

```text
┌────────────────────────────────────────────────────────────────────────────┐
│ Верхняя панель: день, время, веткоины, репутация, очередь, скорость, пауза │
├───────────────┬────────────────────────────────────────────┬───────────────┤
│ Очередь       │ Карта клиники                              │ Сводка дня    │
│               │                                            │               │
│ Пациенты      │ Ресепшен     Зал ожидания                  │ Доход         │
│ Статусы       │ Кабинет 1    Кабинет 2                     │ Расходы       │
│ Срочность     │ Лаборатория  Рентген/УЗИ                   │ Ошибки        │
│               │ Операционная Стационар                     │ Риски         │
├───────────────┴────────────────────────────────────────────┴───────────────┤
│ Нижние вкладки: Клиника / Прием / Персонал / Исследования / Финансы        │
└────────────────────────────────────────────────────────────────────────────┘
```

Визуально:

- белый и голубой интерфейс;
- карта клиники в центре;
- кабинеты разделены четко;
- занятые кабинеты подсвечиваются;
- срочные пациенты получают красный или янтарный маркер;
- свободные кабинеты получают мягкий голубой статус.

## 3. Помещения

### Ресепшен

Функции:

- появление новых пациентов;
- первичная регистрация;
- оценка срочности;
- распределение в очередь.

Игровые параметры:

- скорость регистрации;
- терпение владельцев;
- влияние администратора;
- риск потери пациента до приема.

### Зал Ожидания

Функции:

- показывает очередь;
- отображает настроение владельцев;
- выделяет срочные случаи.

Игровые параметры:

- вместимость;
- комфорт;
- ожидание;
- репутационный штраф при уходе.

### Кабинет 1

Начальный кабинет.

Функции:

- анамнез;
- осмотр;
- простые процедуры;
- базовое лечение.

### Кабинет 2

Открывается на втором этапе.

Функции:

- параллельный прием;
- распределение врачей;
- выбор специализации в будущем.

### Лаборатория

Открывается на третьем этапе.

Функции:

- кровь;
- моча;
- экспресс-тесты;
- мазки.

Влияет:

- повышает уверенность диагноза;
- увеличивает чек;
- требует расходников и времени.

### Рентген / УЗИ

Функции:

- травмы;
- инородные тела;
- беременность;
- опухоли;
- жидкость в полостях.

### Операционная

Функции:

- хирургические случаи;
- срочные операции;
- высокий доход и высокий риск.

### Стационар

Функции:

- наблюдение после операции;
- инфузии;
- тяжелые пациенты;
- длительные кейсы на несколько дней.

## 4. Экран Приема

Открывается при выборе пациента или кабинета.

Структура:

```text
┌──────────────────────────────────────────────────────────────┐
│ Пациент: кот, 8 лет, 4.6 кг          Владелец: тревожный      │
├──────────────────────┬───────────────────────────────────────┤
│ Жалоба владельца     │ Медицинская карта                     │
│ Анамнез              │ Видимые признаки                      │
│ Осмотр               │ Результаты диагностики                │
│ Диагностика          │ Вероятные диагнозы                    │
├──────────────────────┴───────────────────────────────────────┤
│ Действия: вопрос / осмотр / анализы / рентген / лечение       │
├──────────────────────────────────────────────────────────────┤
│ Диагноз, лечение, прогноз, цена, риск, кнопка завершения      │
└──────────────────────────────────────────────────────────────┘
```

Важно:

- диагноз не должен выглядеть как простая угадайка;
- игрок должен видеть, почему уверенность выросла или упала;
- опасные симптомы нужно выделять до диагноза;
- лечение должно зависеть от оборудования и знаний клиники.

Для MVP 1 осмотр разбивается на базовые врачебные действия:

- слизистые;
- дыхание;
- температура;
- локальный осмотр проблемной зоны;
- для отита - осмотр уха;
- для клещевого отита - микроскопия как простая доступная диагностика.

## 5. Экран Персонала

Показывает:

- врачей;
- администраторов;
- ассистентов;
- хирургов;
- лаборантов;
- календарь клиники на семь дней;
- назначенного врача каждой смены;
- рабочие часы клиники;
- выходные и доступность сотрудников;
- усталость;
- опыт;
- специализацию;
- зарплату.

Механика:

- в одном кабинете принимает один выбранный врач; каждый из двух стартовых врачей может работать до трех смен подряд с накоплением усталости;
- клиника может быть открыта каждый день недели;
- расширение часов повышает потенциальный поток, зарплатные расходы и усталость;
- сверхурочная работа должна быть отдельным осознанным решением;
- опыт растет от правильных случаев;
- усталость увеличивает время действий, усложняет коммуникацию и организацию смены;
- специализация улучшает конкретные болезни;
- обучение стоит денег и времени.

## 6. Экран Исследований

Показывает дерево знаний.

Группы:

- терапия;
- дерматология;
- гастроэнтерология;
- эндокринология;
- травматология;
- хирургия;
- экзотические животные;
- диагностика.

Каждое исследование открывает:

- болезнь;
- протокол;
- оборудование;
- снижение риска;
- новый тип пациента;
- повышение среднего чека.

## 7. Экран Финансов

Показывает:

- выручку по категориям;
- расходы;
- зарплаты;
- расходники;
- аренду;
- компенсации;
- прибыль за день;
- динамику репутации;
- средний чек;
- потерянных пациентов.

Нужен не как бухгалтерия ради бухгалтерии, а как объяснение игроку: почему клиника зарабатывает или теряет веткоины.

## 8. Экран Конца Дня

Показывает:

- сколько пациентов пришло;
- сколько принято;
- сколько ушло;
- сколько вылечено правильно;
- сколько ошибок;
- какие болезни чаще всего были;
- какие кабинеты были перегружены;
- что стоит улучшить.

Игра должна давать понятный вывод:

- "Не хватает администратора".
- "Кабинет 1 перегружен".
- "Слишком много ошибок по дерматологии".
- "Лаборатория окупается".
- "Цены слишком высокие для текущей репутации".

## 9. Минимальная Структура Для Следующего Прототипа

В следующем прототипе должны быть только эти экраны:

1. Главный экран клиники.
2. Карта: ресепшен, зал ожидания, кабинет 1, кабинет 2.
3. Экран приема выбранного пациента.
4. Вкладка персонала.
5. Вкладка исследований.
6. Отчет конца дня.

Лаборатория может быть видна как закрытое помещение, но полноценная лабораторная механика подключается только после согласования этапа диагностики.
