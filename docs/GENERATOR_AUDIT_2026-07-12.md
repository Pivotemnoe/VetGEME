## Результат аудита текущего состояния

В исполняемом локальном коде не было перенесенного эквивалента генератора. Поиск не нашел:

- `campaignSeed`;
- `generatorVersion`;
- `generatedDays`;
- `getOrGenerateDay`;
- seeded/deterministic random;
- fingerprint дня;
- `pendingFollowUps` генератора;
- сохранение полностью сгенерированного дня;
- защиту от перегенерации после перезагрузки.

Текущий `campaign.js` оставался фиксированным пятидневным сценарием. Имеющиеся в `game.js` поля `pendingReturns` и `caseJournal` относятся к текущей игровой петле и не заменяют генератор кампании.

## Legacy v1

Контрольная реализация восстановлена из `origin/main` в изолированную область:

- `legacy/generator-v1.js`;
- `legacy/campaign-v1.js`;
- `legacy/campaign-node-v1.js`;
- `scripts/simulate-generator-v1.js`.

Сохранены исходные функции и принципы:

- `campaignSeed` и `generatorVersion`;
- hash и `mulberry32`;
- `getOrGenerateDay`;
- немедленное сохранение `generatedDays`;
- fingerprint;
- восстановление кампании после перезагрузки;
- fallback второго дня при отсутствии реально завершенного случая.

Ограничения v1:

- только пять дней;
- фиксированные шаблоны пациентов из `campaign-v1.js`;
- есть кролики;
- генератор меняет в основном имена, профиль и время;
- `pendingFollowUps` объявлен, но не является полноценным источником повторных визитов;
- медицинские данные не загружаются из отдельного валидированного каталога;
- отсутствуют проверки оборудования, домашних действий и совместимости владельца.

## Generator v2

Новая реализация находится отдельно:

- `generator/content-loader-v2.js`;
- `generator/generator-v2.js`;
- `generator/game-adapter-v2.js`;
- `generator/generator-mode.js`;
- `scripts/simulate-generator-v2.js`;
- `scripts/test-v2-adapter.js`.

Generator v2:

- использует только `tier-01-v2/content`;
- поддерживает семь дней;
- создает и сразу сохраняет план дня;
- не показывает незапланированных пациентов до открытия;
- разрешает незапланированные слоты детерминированно после открытия;
- создает повторные визиты только из завершенных приемов;
- сохраняет личность пациента и владельца при повторном визите;
- не генерирует медицинский текст;
- исключает кроликов;
- проверяет срочность, оборудование, профиль владельца и домашние действия;
- блокирует неизвестную версию сохранения вместо молчаливой перегенерации.

## Сохранения и миграция

- Legacy v1: ключ `pet-clinic-generator-v1`, save version 1.
- Tier 01 v2: отдельный ключ `pet-clinic-generator-v2`, save version 2.
- Старый ключ не изменяется и не мигрируется автоматически.
- При несовпадении версии внутри v2 загрузка блокируется. Перед изменением схемы требуется отдельная миграция, сохраняющая `campaignSeed`, уже созданные дни, outcomes и pending follow-ups.

## Feature flag

Поддерживаются режимы:

- `current` — режим по умолчанию;
- `legacy-v1` — контрольный старый генератор;
- `tier-01-v2` — новый каталог и генератор.

Примеры:

- `?generatorMode=current`
- `?generatorMode=legacy-v1`
- `?generatorMode=tier-01-v2`
